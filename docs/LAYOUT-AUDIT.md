# Current health tracker layout audit

This audit starts from the current Food, Body comp and Workouts application on 15 October 2026. Historical reports in `UI-AUDIT.md`, `UI-AUDIT-STATUS.md` and prior chat turns do not count as evidence for this audit. A route inventory is an obligation to test, not evidence that its pixels passed.

## Primary phone and emulation

OPPO's [global Find X9 Pro specification](https://www.oppo.com/en/smartphones/series-find-x/find-x9-pro/specs/) identifies model CPH2791 and lists a 6.78-inch display, native resolution **2772 × 1272 pixels**, 450 PPI and a maximum refresh rate of 120 Hz. The [official India specification](https://www.oppo.com/in/smartphones/series-find-x/find-x9-pro/specs/) independently agrees on resolution and pixel density. Both were opened through the browser research connector during this audit.

Portrait native dimensions are therefore 1272 × 2772. The derived height-to-width ratio is `2772 / 1272 = 2.179245283`, equivalent to **19.61320755:9**, approximately 19.6:9. The specification's 95.5% screen ratio is the screen-to-body figure; it is not an aspect ratio.

The manufacturer does not publish the Chrome CSS viewport or browser device-pixel ratio. **424 × 924 CSS pixels at DPR 3** is a derived emulation that exactly reproduces the panel's 1272 × 2772 pixel dimensions and aspect ratio. It is not a measurement of the owner's phone. Additional widths test display-density sensitivity; browser controls, Android status/navigation areas, display-size settings and the keyboard change usable content height separately. Physical ColorOS/Chrome behavior remains a device verification limit.

The shared harness records actual viewport, DPR, text scale, mode, fixture, source identity and screenshot path per case. The target set includes the primary derived phone, a narrower density case, a small-screen case, a wide/landscape case, enlarged text, reduced usable height and keyboard stress. The final case ledger, rather than this planning paragraph, determines which combinations were actually exercised.

One screenshot does not establish all five. Final reporting must list fresh case and capture counts, named fixes with retest evidence, remaining gaps and physical-device limits. ## Verification limits

All health records used by the browser audit are synthetic. GitHub reads and writes are intercepted and validated; mock saves exercise real application handlers without changing the canonical health file. Prototype route overrides are labelled with their own asset hashes and excluded from acceptance. Failed originals, audit-setup corrections and their explicit passing replacements remain inspectable.

Live Open Food Facts requests were blocked in this environment. Barcode lookup states use declared public-API fixtures, while decoding is exercised on a synthetic camera stream. The local OCR engine and offline service-worker path are exercised directly. Physical OPPO hardware, ColorOS display settings, the native keyboard, native permission/camera interfaces, installation UI and the OS print dialog remain unverified. Browser handoff and app-owned return/error states are tested separately. Computed contrast through translucent backgrounds is an estimate supplemented by pixel inspection, not a WCAG certification.
