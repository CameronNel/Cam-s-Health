# Evidence rules and baseline handoff

The 6 October 2026 user request requires screenshot inspection of every screen, menu and submenu, including the bottom of every scrollable surface, by both builder and independent reviewer. A 100% release goal does not authorize invented approval scores. Every visible failure blocks approval; shell correctness and DOM checks are separate evidence.

The first inventory has 13 screen/detail routes, 56 menu/disclosure cases and 23 empty/error/loading/offline/update variants (92 cases). Additional behavioral checks cover native form options, authorization and save failures, keyboard, enlarged text, timers, cleanup operations, Gmail import and real-motion transitions. Run `source-inventory.mjs` after adding an app menu and update the inventory before review. Samsung/Health Connect import menus added after the initial inventory also require capture cases.

The reusable fixture isolates GitHub reads/writes, private life APIs and service-worker lifecycle, uses synthetic data, and never mutates a real account. Base fixtures validate with the app's current validators. Text scaling is applied in one measured pass using inline priority and explicit placeholder styling so CSS `!important` cannot silently leave form text unscaled. Keyboard simulation focuses the field at resting height and then reduces the viewport; an initially short viewport alone is insufficient.

Baseline evidence under `/tmp/cams-life/night-audit/baseline` contains 35 viewport captures for 11 selected cases at 424px. All 35 were visually inspected by the infrastructure builder, together with all 16 uploaded Samsung references. Material baseline defects were reported to the root builder: unsaved prompt overlaps underlying text, full-width sticky header covers card tops while scrolling, update recovery retains Georgia/system typography, and half-width save labels become three lines at 200% text. Baselines were captured before the builders completed their fixes and cannot approve the final candidate.

The initial inventory smoke run under `/tmp/cams-life/night-audit/inventory-smoke` captured all 92 cases and 284 viewport images with no harness failures, browser page errors or unmocked network requests. Those 284 images were generated during active edits and have NOT all been visually inspected by the infrastructure builder. Final per-menu reviewers must inspect freshly captured candidate evidence. DOM clip, target and obstruction outputs are candidates to investigate, not automatic judgments.

Service-worker install and caching integrity require the app's separate genuine PWA upgrade tests; the visual shim is deliberately not proof of caching behavior. Google/GitHub authorization pages and native browser permission/selection dialogs are external UI. Validate their entry points/options and inspect any available browser capture without pretending their pixels are app-owned.
